# battle(def / action / effect / modifier / cultivator / controller / ai)

## 职责

五行斗诀的回合制战斗内核，纯C++、不涉及画面和UE，全部放在`namespace wxdj`里；被`puzzle_wxdj`使用，同一份源码也被`ai/transformer/env.cpp`直接编译成训练环境，网页版`Online/public/ai.html`里有逐项对拍过的JS移植。

- `def.h`：平衡系数、五行属性/克制表/双招合成属性表、阶位及其武力要求、阶段/招式/效果类型枚举、玩家五行属性位掩码、招式名拆家族/式号的`FamilyOfName`/`FormOfName`。
- `action.*`：招式(跳过、积攒真气炸弹、释放炸弹、单招`SingleAction`、双招`DualAction`)。`SingleAction`的拷贝构造会深拷贝每个效果(出招用的是副本，运行时改威力/消耗不污染招式表)。
- `effect.*`：招式附带效果(物理、穿透、减伤、反弹、吸收、禁锢、持续伤害、回复真气/武力/健康、连招增伤、静止增伤、护盾)，以及金火灼烧/金水锈蚀/土火扬尘/土水泥沼四种场地效果。
- `modifier.*`：特性(`Modifier`，装备/秘诀/丹药/场地共用的外部效果)及其文本解析`ParseModifier`。
- `cultivator.*`：修炼者的属性、阶位和招式表，`LoadActions`解析招式文件(格式见`Resource/README.md`)；连招链、敏捷、炸弹存量、五行属性、抗性。
- `controller.*`：回合控制器，`StartTurn → ActionTurn → CheckTurn → EndTurn`四阶段结算，战斗日志(`Log`)通过`GetNews()`取出。
- `ai.*`：对战AI的C++推理，见本文"AI"一节。

## 回合流程

- `StartTurn`：清空本回合状态位和跳过敏捷；场地效果的回合计数减一并移除用完的；`ExecEffect(STAGE_START)`(每回合类特性、禁锢生效、持续伤害/回复真气/回复武力/回复健康各结算一次)；每人回复真气`recover`并回复敏捷`agiRecover`。真气回复量记在`regenMP`里，空炸弹要撤销它。
- `ActionTurn`：按出招者逐个处理，扣真气、记日志、挂上招式自带的"不需要命中"的效果(回复真气/武力/健康、护盾)。
- `CheckTurn`：结算命中/闪避/伤害/炸弹；**结算期间看到的场地效果都是回合开始时的**，结算完才统一清除并生成新的(见"场地效果")。
- `EndTurn`：`ExecEffect(STAGE_END)`(结束时机的特性、护盾回合数减一)、特性持续回合减一、`UpdateRealm`。
- 状态位`status[i]`：`0x01`=本回合被禁锢(`StartTurn`时由禁锢效果置位并移除该效果)，`0x02`=本回合在积攒(易伤用)。
- 死亡判定：`健康<=0`或`武力<=0`；真气超过上限2倍直接死亡(爆体)；真气不足出招时透支，不足部分按2倍扣武力(`Cultivator::ConsumeMP`)。调用方要在每次`StartTurn`之后也检查存活(每回合开始类特性可能致死)，`WxdjPuzzle::ResolveTurn`已处理。

## 关键设计

### 全局系数(`def.h`)
| 系数 | 值 | 含义 |
|---|---|---|
| `DUAL_COST_FACTOR`/`DUAL_POWER_FACTOR` | 1.0/0.6 | 双招消耗=两招消耗之和x1.0，威力=两招威力之和x0.6 |
| `ACCUMULATE_FRACTION` | 0.2 | 一次积攒消耗当前真气的比例，再乘修炼者的炸弹倍率存进炸弹 |
| 炸弹倍率 | 按阶位 | 3-1=1.0，3-2=1.2，3-3=1.5，3-4=1.9，3-5=2.4，3-6=3.0，4-1=3.7，4-2=4.5，4-3=5.6，4-4=7.0，4-5=8.5，4-6=10.0；同一阶位的各式共用阶位最大式(`RealmMaxForm`/`BombMultiplierOfForm`)，构造`Cultivator`时传入，默认`BOMB_ACCUMULATE_MULTIPLIER`=10 |
| `BOMB_HIT_FACTOR_PASSIVE`/`ACTIVE` | 0.4/0.7 | 炸弹打没出招的对手：B x0.4；打出了招的对手：(B-对手威力) x0.7(出招自带抵消和减伤/反弹，所以不能调小) |
| `BOMB_BACKFIRE_FACTOR` | 0.2 | 自己反噬 B x0.2；双方互扔：双方各受 (B1+B2) x0.2 |
| `BOMB_RUST_FACTOR` | 0.5 | 锈蚀场地下以上几处系数统一为0.5 |
| `ACCUMULATE_VULNERABILITY` | 0.2 | 积攒的那一回合，自己受到的所有伤害多20% |
| `SKIP_AGI_FACTOR` | 2 | 跳过时闪避用的敏捷倍数 |
| `SKIP_STREAK_EXTRA_LOSS` | 0.5 | 连续跳过每多一次多扣的敏捷 |
| `FIELD_EFFECT_ROUNDS` | 3 | 场地效果持续的完整回合数 |
| `ELEM_POWER_BASE`/`ELEM_RESIST_OWNED`/`ELEM_SHIELD_KEEP` | 1.5/1.5/0.5 | 玩家五行属性相关，见"玩家五行属性" |

### 招式与双招
- 属性克制(`ATTRIBUTE_COUNTERS`)：水克火、火克木、木克水、土克金、金克木、木克土；五行克金木水火土；金木水火土五个元素都克无属性，无属性和五行之间没有克制。双方对撞时，被克制的一方威力减半。
- 双招的两招必须同式(招式名里"第X式"相同)，由`Cultivator::GetAction(idx1, idx2)`/`(name1, name2)`兜底，不同式返回跳过(否则可以拿高式招式搭低式的其它属性招，便宜地改变高式招式的属性)。双招属性按`DUAL_ATTRIBUTE_PRIMARY`合成；两招有同种类效果时只取第一招的(顺序互换结果就不同)；`increase`/`static`不并进双招的效果列表，两个基础招式各自带自己的。
- 释放炸弹的时刻才取出炸弹能量(`BombPower()`并清零)，能量写进战报"(能量N)"；`bomb_power`特性在此时调整。
- **空炸弹**：炸弹能量为0时释放，等于一次纯跳过——不出招、不翻倍敏捷、不损失敏捷(闪避照常用自己的敏捷)，代价是这回合不回复真气(`UndoMP(regenMP)`)；炸弹有能量时才是真炸弹。`CheckTurn`里空炸弹被换成`SkipAction`。
- **禁止积攒**：`Cultivator::SetNoAccumulate(true)`(PvE敌人)后选积攒当作跳过：`ActionTurn`开头换掉，`CheckTurn`靠`status`没有积攒位认出同样换掉(付跳过的敏捷代价、不算积攒、不算静止、不吃易伤)。默认关，PvP不受影响。UE端目前没有开启。

### 敏捷与跳过
- 敏捷是小数。跳过(含被禁锢而无法出招，选积攒不算)要付`SkipLoss()`=`agiLoss`+0.5x连续跳过次数(默认1、1.5、2……，加`skip_agi`特性)，敏捷不能低于1。付得起(`CanDodge()`：付完不低于1)时，这次跳过用**翻倍**的敏捷闪避并扣敏捷；付不起时不翻倍、不扣敏捷，但仍用自己原来的敏捷闪避。出招、积攒、真放炸弹后连续次数清零，空炸弹不算跳过也不清零，被禁锢而被迫跳过计入。每回合开始恢复`agiRecover`点，不超过上限。
- 闪避概率 = 防守方敏捷² / (攻击方敏捷² + 防守方敏捷²)，只用于对手"没有被正面应对"的普通招式(对方跳过/积攒/被禁锢/招式指向别人)；炸弹和对撞不走闪避。被禁锢又选了积攒的人用自己当前敏捷闪避(不翻倍)。锈蚀场地下闪避率为0。
- 标准初始敏捷随阶位变化：5 + 阶位最大式/4(3-1=5.25 … 4-6=10)。UE小游戏固定用4-6阶位的10。

### 对撞与结算(`CheckTurn`)
- 一方对没有正面应对的目标出普通招：先闪避判定，再命中判定(`RollHit`)，命中后`HitSuccess`触发禁锢/持续伤害/带"需要命中"的回复，再按全额威力`TakeDamage`。
- 双方互相出普通招：每对只处理一次；先按克制减半，威力大的一方对另一方造成**威力差**的伤害，相等则双方都不受招式伤害；命中判定只用先手座位一次，命中则双方的命中类效果都触发；穿透在对撞里按**较小的那个威力**x对方属性对应的穿透比例追加伤害。命中失败(含扬尘下判定失败)写"出招失败"。
- 炸弹和普通招的对撞：炸弹方的能量大于对方威力时对方受差额x`BOMB_HIT_FACTOR_ACTIVE`；对方威力高到一定程度时炸弹方反受伤害，细节见`CheckTurn`里三个分支。炸弹对没出招的目标按`PASSIVE`系数，对自己按反噬系数。炸弹自带100%物理效果，所以伤害全部扣健康。
- 被禁锢的一方(除积攒外)这回合的招当作跳过：它招式上的减伤/反弹/吸收/物理等效果也不生效。

### 伤害结算顺序(`TakeDamage`)
免疫 → 场地倍率(灼烧1.5，`field_mult`特性按出手方加减) → **受到伤害乘区**(1 + 易伤加和 − 减伤比例，加算；易伤包括积攒回合固定的0.2和`dmg_taken`特性，只增不减，所以乘区至少是1−减伤比例) → 属性抗性(伤害x2/(抗性+1)，抗性为1时跳过) → 护盾 → 物理拆分 → 反弹 → 实际扣血 → 触发类特性 → 吸收。
- **物理效果**：`physical`后跟7个比例(对方这一招的属性：无/金/木/水/火/土/五行)，表示这一招造成的伤害里有多少比例转换成物理伤害(扣健康)，剩余仍是招式伤害(扣武力)；对方没出攻击招(跳过/积攒/被禁锢)时按"无"属性取值。不带参数的`physical`等于全部100%(炸弹)。穿透/反弹的追加伤害、持续伤害的即时伤害也走同一套转换。伤害日志因此可能同时带武力伤害和物理伤害两部分。
- **扣血规则**(`Cultivator::TakeDamage`)：招式(武力)伤害一定扣等量武力；单次伤害不小于当前武力的60%时额外扣等量健康，不小于30%时额外扣一半健康；物理伤害只扣健康。
- **反弹是减伤的升级版**：有反弹的一方只承受反弹之后剩下的伤害，被反弹的部分全部还给攻击者(反弹和减伤同时存在时先减伤再反弹)。只反弹穿过护盾的部分；没有出手方的伤害(持续伤害)不反弹。反弹回来的伤害不再乘灼烧，且递归深度上限8层(否则灼烧x1.5会让双方互相反弹越弹越大，比例>2/3时递归爆栈)。
- 持续伤害、炸弹自伤、反弹回来的伤害同样先过乘区、抗性和护盾；反弹回来的那一份也会触发特性(出手方/受击方按反弹方向对调)。
- `ExecEffect`里持续伤害结算会让护盾被打光而从`effects[i]`移除，所以循环里按值持有`shared_ptr`并在伤害后重新定位下标，不要改成持有引用/下标。

### 场地效果
- 金火→灼烧(伤害x1.5)，金水→锈蚀(不能闪避，炸弹系数0.5)，土火→扬尘(命中率-50%，即乘区1+命中特性-0.5)，土水→泥沼(出招消耗x1.5，与`cost`特性先后各自取整)。同类型再次生成会刷新。
- 来源：双方出招的最终属性对撞(`CheckReaction`)；双招用它两个基础招式的属性自造，但**只有这个双招未命中**(被闪避，或扬尘下命中判定失败，对撞时命中判定失败也算)才计入，且对撞里已经产生了反应时不再自造；特性`now_field`。
- 清除：本回合各方出招的属性(取被禁锢改成跳过之前的原属性)清除相克的场地：金灭扬尘/泥沼，水灭灼烧/扬尘，火灭锈蚀/泥沼，土灭灼烧/锈蚀；先清除、再加上本回合新生成的，所以新生成的不会被同回合的出招清掉。特性`now_field`/`clear_field`是立即类，不受影响。
- 持续回合数不含出现的那一回合：效果内部存`FIELD_EFFECT_ROUNDS+1`回合，每回合开始减一，减到0立刻消失。第5回合结算后出现的场地，在第6、7、8回合生效，第9回合开始时消失；`GetEnvironment()`返回的"还剩N回合"出现时和生效的第一个回合都是3。

### 连招增伤`increase r`
每个修炼者记着上一回合出的招(单招=1个，双招=两个基础招式)各自的"家族+式号+已连续步数"(`PeekChain/CommitChain`)。本回合出家族F的第k式，链里有(F, k-1)就是步数+1，否则步数0(新起点，没有加成)；积攒/炸弹/跳过/被禁锢/空炸弹把链清空；命中与否不影响；双招里只要包含这一招就算连着。威力 = 基础威力 x (1 + r x 步数)，双招每个基础招式用自己的r和步数。战报：每个有增伤的基础招式一行"连招增伤"(`Log.name`="招式名|r%|步数"，`amount`=r x 步数的百分比)，双招再加一行合计(`name`为空)。

### 出招威力的乘区装配(`Controller::ApplyPower`)
先算完所有乘区再进对撞/炸弹结算，结果用`Action::SetPower`写回招式对象，所以`CheckTurn`里读`GetPower()`的分支不用改：
`单个基础招式 = (基础威力 + base_power特性加成) x (1 + r x 步数)`；双招 = `DUAL_POWER_FACTOR x Σ`；然后依次乘 自己拥有该属性时的同属性倍率 x 增伤乘区(1 + `dmg_dealt`加和 + 静止增伤) x 暴击(1+暴击伤害)。同乘区内加算，乘区之间相乘。没有任何加成时不动威力，也不多抽随机数(保证没有新规则时和以前逐位一致)。结果夹到int范围。场地乘区在`TakeDamage`里，不在出招威力里。

### 静止增伤`static 比例`(家族"天动万象")
对"静止"的敌人增伤。静止 = 敌人这回合**积攒炸弹**，或**没被禁锢却放了空炸弹**；跳过不算，被禁锢强制跳过也不算。`ActionTurn`开头按双方出的招一次算好`staticNow`(因为放炸弹会清空炸弹存量)。比例加进增伤乘区；双招两招都带static只取第一个。触发时战报多一条"静止增伤"。

### 护盾`shield 盾量比例 持续回合数`
- 盾量 = 出招者**武力上限** x 比例(`ActionTurn`出招时算，不需要命中)，盾带出招者**当前**的五行属性；每次出招一块新盾，各自独立计时、同时存在。持续回合含出招当回合，每回合结束减一，到0或强度打光就移除。运行时生成的盾(`now_shield`特性)直接带强度。
- 受伤时先过减伤/抗性，**再过护盾**(`ApplyShield`)：每块盾都减去同一个伤害值，穿透量 = 伤害 − 最大那块盾的有效容量(多块盾只是各自计时，容量不叠加)；盾的五行属性覆盖伤害属性时该盾扣的量减半(向上取整，等价于容量翻倍)，盾打光后剩下的伤害不再减半。穿透量再进入物理拆分/反弹/吸收。同时保护武力和健康。
- 战报："获得N点护盾"(`subject>=0`)、"的护盾抵挡了N点伤害"(`subject=-1`)。

### 玩家五行属性(`Cultivator::SetElements/Resist/ElemPowerMul`)
- `elements`是位掩码(第n位=`ATTRIBUTE_TYPE`值n，与`Modifier.attrMask`同一编码)，默认0=无属性，此时所有五行规则都不触发，战斗结果和随机数序列与没有这套规则时逐位一致。**PvP强制双方无属性**(`online.js`的`newBattle`显式`setElements(0)`)。入口：网页`ai.html`状态条的"五行"勾选框；UE的`WxdjPuzzle::SetParam`(剧情参数`elem=金木 enemy_elem=火`)。
- "覆盖"判定`ElementCovers(mask, attr)`：无属性永不覆盖；金木水火土要有对应位；五行(ALL)要五位齐全。双招用合成后的属性。
- **威力**：自己覆盖招式属性时，招式威力x`ElemPowerMul`(基础1.5 + `elem_power`加和，夹到>=0)，是独立乘区。
- **护盾**：见上。**抗性**：每个玩家对金木水火土各有抗性x(100%=1.0)：拥有该属性基础1.5，否则1.0，加`resist`特性的增量，夹到>=0；实际伤害 = 伤害 x 2/(x+1)(1.5→x0.8，0→x2)。五行伤害要玩家五个属性都拥有才计算，取五个抗性的平均值；无属性伤害不处理。
- AI(PvP模型)的特征没有五行信息，对五行玩家的判断会偏差。

## 特性系统(外部效果，`modifier.h/.cpp`)

装备/秘诀/丹药/场地都用同一套"特性"(`Modifier`)：**种类 + 数值 + 属性掩码 + 条件 + 持续回合 + 执行时机 + 来源**，给谁加由`Controller::AddModifier(holder, m)`的持有者参数决定，存在`Cultivator::Mods()`里。同种类的数值**取加和，持续时间各算各的**。没有特性时行为与没有这套系统时一致；暴击基础值`SetCritBase`默认0(不暴击、不多抽随机数)。网页版`ai.html`有同样的实现和"特性调试"面板，C++与JS逐场景对拍一致。

文本格式：`mod <种类> <数值>[%] [attr=…] [cond=…] [dur=…] [timing=…] [src=名字]`，`#`开头是注释。
- `attr=`：逗号分隔 none metal wood water fire earth all(五行属性的招) elements(金木水火土) any，省略=全部(每个属性一个bit，按`ATTRIBUTE_TYPE`)。
- `cond=hp<50`：持有者的hp/atk/mp/agi占上限的百分比低于(<)/高于(>)阈值才生效(独立参数，可挂在任意种类上，查询数值时判断)。
- `dur=`：持续回合数，-1=永久(默认)；每回合`EndTurn`减一，到0移除。建议在回合之间添加(回合中途添加的，那一回合算第一回合)。
- `timing=start|end`：每回合类的执行时机，回合开始(默认)或结束。
- 数值后加`%`：每回合类/立即类按上限的百分比，触发类按这次伤害量，`base_power`按该招基础威力，`*_max`按基础上限。

| 种类 | 含义和接入点 |
|---|---|
| `mp_round atk_round hp_round` | 每回合回复(+)/扣除(-)真气/武力/健康，`ExecModifiers`在回合开始/结束执行；武力/健康扣到0会死(`Cultivator::AdjustATK/AdjustHP`)；真气回复仍受上限和2倍爆体约束 |
| `skip_agi` `agi_recover` `agi_max` | 跳过扣敏捷调整(`SkipLoss`)、每回合敏捷回复调整(`RecoverAGI`)、敏捷上限增减(`GetMaxAGI`)；初始敏捷只在开局赋值，之后改的都是敏捷上限 |
| `mp_max` | 真气上限增减(`GetMaxMP`有效上限，`GetBaseMaxMP`基础上限)；"真气>2x上限即死"的阈值跟着有效上限走 |
| `acc_ratio` `bomb_power` | 单次积攒比例调整(基础0.2，夹到0~1)；炸弹威力增减(炸弹乘区=积攒能量 x 场地 x 炸弹倍率，和招式乘区无关) |
| `base_power` `dmg_dealt` `dmg_taken` | 招式乘区：x属性基础威力(加算进基础伤害)、自己造成伤害增减(增伤乘区)；`dmg_taken`是易伤，**只增不减**(`ParseModifier`对负数返回false，`ModifierSet::Add`忽略负数，`Controller::Vulnerability`取max(0, 加和))，和减伤效果同一个乘区 |
| `crit_rate` `crit_dmg` | 暴击率/暴击伤害增减；暴击倍率=1+暴击伤害，出招时掷一次(座位顺序固定，保证联机/重放一致) |
| `field_mult` | 场地x属性伤害倍率增减，以1为基准(灼烧本身是1.5，所以灼烧时再+0.5就是x2.0)，在`TakeDamage`里按出手方的特性算 |
| `dodge` `hit` | 闪避率/命中率乘区，和锈蚀/扬尘在同一乘区、数字加和：闪避区=1+加和−锈蚀(1)，最终闪避率=原闪避率x闪避区；命中区=1+加和−扬尘(0.5)，够1必中不抽随机数。命中判定用先手座位的命中乘区 |
| `cost` | x属性消耗调整(0.2=+20%)，和泥沼x1.5同层先后各自取整 |
| `deal_mp/atk/hp` `take_mp/atk/hp` | 造成/受到x属性伤害时给持有者回复(+)/扣除(-)真气/武力/健康，`ApplyDamageTriggers`；%=按这次伤害量 |
| `rebound` `immune` | 受到x属性伤害的反弹比例(加到反弹效果上，夹到0~1)；免疫x属性(该属性伤害变0) |
| `now_mp/atk/hp/agi` `now_field` `clear_field` `unlock` | 立即类：添加时马上执行、不保存、没有持续回合；`now_field`的数值是场地效果枚举(11灼烧 12锈蚀 13扬尘 14泥沼)；`unlock`移除禁锢 |
| `now_shield` | 立即类：立即给持有者加一块护盾，数值=强度，`attr=`=盾的五行属性(金木水火土可多选，`all`=五个齐全，不写=无属性盾)，`dur=`=持续回合(-1=不随回合衰减，到被打光)；日志沿用"获得N点护盾" |
| `resist` | 对x属性(金木水火土)的抗性增减，数值是**增量**(0.5=+50%)；常驻类，支持`dur`/`cond`/`src` |
| `elem_power` | 自己拥有的属性的招式的威力倍率增减(基础1.5，增量)，夹到>=0、无上限；`attr=`限定招式属性；常驻类 |

特性触发的资源变化在战报里写成`EFFECT_TRAIT`，`name`="资源|来源"(资源是mp/atk/hp/agi)。

## AI(`ai.h/.cpp`，通用对战模型的C++推理)

- Perceiver式小Transformer(约92万参数)：输入"双方招式 + 当前局面 + 最近8回合出招记录"，输出招类(跳过/积攒/炸弹/单招/双招) → 第一个招式 → 双招的第二个招式(必须同式)。结构和特征照`ai/transformer`的`model.py`/`features.h`/`env.cpp`，权重文件`Resource/act/ai_weights_pvp.bin`由`export_weights.py`导出(文件头"WXNN"，版本1)，和网页版`ai_weights_pvp.js`是同一份。
- `Load`会校验输入层/潜变量/分类头的形状与`features.h`的`FM`/`SD`/`HD`/`HK`一致，对不上就拒绝加载(用错权重会出怪招)；**目前只认PvP维数(招式83/局面49)的权重**，PvE权重(90/89维)需要让`ai.cpp`按权重维数调用`MoveExtrasPvE/StateExtrasPvE`才能接入。`ai.cpp`的`FillState`/`ActionRecord`是`env.cpp`同名函数的复制，改特征时`features.h`、`env.cpp`、`ai.cpp`和网页JS必须同步。
- 用法：每回合`StartTurn`之后`BeginRound`记下出招前状态，`Choose`出招(候选是每个家族的最高式)，`EndTurn`之后`EndRound`用本回合的日志(闪避记录)和状态变化攒出招记录；新战斗`Reset`。`Choose`推理出错会停用AI并返回空指针，调用方退回随机出招。
- 对拍程序`ai/transformer/ai_test.cpp`：同一场景下C++与网页JS的logit差应<=1e-4。

## 数值平衡

平衡目标：以`无招第一式`(消耗100/威力200，无属性无效果)为基准，让同一式里每个家族的"价值"相当，且不存在压倒性策略。招式表的具体数值以`Resource/act/xiaohua.txt`为准(文件头注释记着调整历史和每个家族的效果变化规则；当前18个家族x20式=360个招式)，**规则改动之后表里的"第20式实测强度"都需要重新评估**，最新一轮评测汇总见`ai/transformer/report_all.md`。

- **评测方法**：自博弈训练AI(见`ai/transformer/README.md`)，均衡时每个招式的使用率应当接近，长期远高于/远低于平均就说明偏强/偏弱；强弱度量方法是把无招的威力临时加x%(消耗不变)得到"价值曲线"，家族的价值落在曲线哪一点就说它"相当于无招多/少x%的威力"。招式使用率的测量误差约±30%，±10以内的威力/消耗差异没有意义；均衡不唯一(同一张表可能落在"炸弹为主"或"单招双招拉锯"两种局面)。
- **经验价值换算**(早期规则下的结果，作数量级参考)：威力+1 ≈ 真气-1.2；回复类(伏羲九针)和减伤/反弹类(海龙金身/金钟罩，会作用在伤害很大的炸弹上)价值远大于直觉，效果数值要压得很小；禁锢概率偏强；穿透/持续伤害/回复真气偏弱；物理效果没有可调数值，靠消耗压价。
- **招式表生成规则**：第1式和第20式是手调锚点；第2~19式的消耗/威力/定时效果(dot/rebate/recover/cure)的立即量和每段量，按"该家族锚点相对无招同式数值的比例"在第1式和第20式之间线性插值，再乘无招同式的数值(rebate用无招的消耗，其余用无招的威力)；比例类效果(穿透/物理/禁锢/减伤/反弹/吸收)不从0涨，而是从第20式数值的一半起线性涨(R(k)=R20x(20+k)/40)；轮次和间隔不动。
- **标准初始属性**(训练和评估用，`gen_pool.py`的`stage_stats`按公式生成：健康 = 基准x第1式比例x威力尺度x0.6^t，武力 = 基准x第1式比例x威力尺度x0.8^t，真气 = 基准x第1式比例x消耗尺度x1.2^t，每回合回复 = 20x消耗尺度x1.2^t，其中 t = 0.8 x min(1, max(0, (式-3)/9))；第20式始终是基准健康1000/武力1200/真气800，第1式的比例按`FIRST_STEPS`随阶位最大式线性插值到1)：

  | 阶位 | 包含的式 | 健康 | 武力 | 真气 | 每回合回复真气 |
  |---|---|---|---|---|---|
  | 3-1 | 1 | 600 | 800 | 1000 | 20 |
  | 3-2 | 2 | 760 | 1010 | 1190 | 24 |
  | 3-3 | 3 | 970 | 1270 | 1410 | 29 |
  | 3-4 | 4 | 1170 | 1560 | 1690 | 35 |
  | 3-5 | 5 | 1430 | 1930 | 2060 | 43 |
  | 3-6 | 6 | 1730 | 2380 | 2490 | 52 |
  | 4-1 | 7-8 | 2330 | 3280 | 3270 | 71 |
  | 4-2 | 9-10 | 3370 | 4940 | 4760 | 105 |
  | 4-3 | 11-12 | 4860 | 7420 | 6910 | 156 |
  | 4-4 | 13-14 | 7480 | 11500 | 9800 | 227 |
  | 4-5 | 15-17 | 13300 | 20200 | 14900 | 358 |
  | 4-6 | 18-20 | 25800 | 38900 | 24800 | 619 |

  UE小游戏双方固定用4-6阶位这一行(`puzzle_wxdj.cpp`的`STANDARD_*`)。各阶位抽测对局回合数约12~17(要求5~20)。
- **强度与属性的关系**：对称对战中强度大致正比于 `健康^a x 武力^1.0 x 真气^0.65`，a从第1式的约0.3增长到第10式及以后的约0.77。保持强度：健康x1.3配武力x0.8(或真气x0.6)；武力x1.2配真气x0.76。武力最适合作"调节难度"的旋钮，真气次之，健康最敏感。
- **局限**：评测用的对打双方属性相同、招式选择较均匀、模拟次数压低，强弱度量误差约±5%；游戏里的敌方AI是通用模型，不是评测用的表格式策略。

## 依赖关系

- 仅依赖标准库。被`puzzle_wxdj`使用；`ai/transformer/env.cpp`以`#define private public`的方式直接读写`Cultivator`/`Controller`的私有成员(训练环境专用，改这些类的成员名要同步改`env.cpp`)。
- 全部对象由本DLL(Wxdj.dll)自己分配、自己释放，不跨DLL传递，不涉及跨DLL`new`/`delete`问题。
- 招式文件由调用方(`WxdjPuzzle`)通过post查到路径后传给`Cultivator`构造函数；文件必须是UTF-8(招式名直接显示在Canvas上)。
