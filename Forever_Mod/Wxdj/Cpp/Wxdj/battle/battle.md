# battle(def / action / effect / cultivator / controller)

## 职责

五行斗诀的回合制战斗内核，纯C++、不涉及画面和UE，全部放在`namespace wxdj`里：

- `def.h`：五行属性/克制表、阶位及其武力要求、阶段/招式/效果类型枚举。
- `effect.*`：招式附带效果(物理、穿透、减伤、反弹、吸收、禁锢、持续伤害、回真气/武力/健康，以及金火/金水/土火/土水场地效果)。
- **物理效果的参数**：`physical`后跟7个比例(对方这一招的属性：无/金/木/水/火/土/五行)，含义是"这一招造成的伤害里有多少比例转换成物理伤害(扣健康值)，
  剩余部分仍是招式伤害(扣武力值)"，和穿透一样按对方属性分别设置；对方没有出攻击招(跳过/积攒/被禁锢)时按"无"属性取值。不带参数的`physical`等价于全部100%
  (真气炸弹就是这样)。穿透/反弹的追加伤害、持续伤害的即时伤害也走同一套转换。伤害日志因此可能同时带武力伤害和物理伤害两部分。
- `action.*`：招式(跳过、积攒真气炸弹、释放炸弹、单招、双招)。
  双招的两招必须同式(名字里"第X式"相同)，由`Cultivator::GetAction(idx1, idx2)`/`(name1, name2)`兜底，不同式返回跳过。
- `cultivator.*`：修炼者的属性、阶位和招式表，`LoadActions`解析`xiaohua.txt`格式的招式文件(`#`开头为注释行，招式行后跟若干效果行)。
- `Cultivator::GetBomb()`：已积攒的真气炸弹能量(界面显示"释放真气炸弹(N)"和判断能否释放用)，是对原版唯一新增的接口。
- `controller.*`：回合控制器，`StartTurn → ActionTurn → CheckTurn → EndTurn`四阶段结算，战斗日志(`Log`)通过`GetNews()`取出。

## 关键设计

- 从老工程`Source/WXDJ`原样迁移，规则不改；只做了`namespace wxdj`、去BOM、去掉控制台输出、
  `def.h`里的全局`const map`改`inline const`(避免每个编译单元一份)。
- 全部对象由本DLL(Wxdj.dll)自己分配、自己释放，不跨DLL传递，不涉及跨DLL`new`/`delete`问题。
- 招式文件由调用方(`WxdjPuzzle`)通过post查到路径后传给`Cultivator`构造函数；文件必须是UTF-8
  (招式名直接显示在Canvas上)。

## 依赖关系

- 仅依赖标准库。被`puzzle_wxdj`使用。

## 数值平衡(2026-10-23)

平衡目标：以`无招第一式`(消耗100/威力200，无属性无效果)为基准，让第一式里每个招式的"价值"相当，且不存在压倒性策略。
评测方法是**自博弈训练AI**：对给定招式表，训练一个分层策略(先选类别：跳过/积攒/放炸弹/单招/双招，再选具体招式)，
双方互相当对手(对手取最近若干个历史快照的混合)，不写任何"真气不够就跳过"之类的硬规则，什么时候出招、什么时候等回复都由学习得到；
均衡时每个招式的使用率应当接近，使用率长期远高于/远低于平均就说明偏强/偏弱。

### 全局系数(`def.h`)
| 系数 | 旧 | 新 | 原因 |
|---|---|---|---|
| `DUAL_COST_FACTOR` 双招消耗 | 0.75 | 1.0 | 旧值下学出来的均衡里双招占约70%，单招和炸弹几乎没人用 |
| `DUAL_POWER_FACTOR` 双招威力 | 1.2 | 0.6 | 同上；新值下双招≈1.2×单招威力、约2×消耗，是"更强但很费真气"的选项 |
| `ACCUMULATE_FRACTION` 积攒转化 | 0.4 | 0.5 | 让"积攒→放炸弹"成为和单招、双招并列的玩法 |
| `BOMB_HIT_FACTOR` 炸弹命中 | 0.8 | 0.75 | 避免炸弹过度压制(新值下炸弹循环约占40%的出招次数，战斗约10~14回合) |
| `BOMB_BACKFIRE_FACTOR` 炸弹反噬 | 0.4 | 0.3 | 旧值下互放炸弹常同归于尽 |
新系数下训练得到的类别使用率大致为：跳过14%、积攒25%、放炸弹20%、单招22%、双招18%。

### 招式表(`Resource/act/xiaohua.txt`)
价值换算(在学出来的策略下实测)：威力+1 ≈ 真气-1.2；1点真气≈0.8点威力。各效果的价值远大于直觉：
回复类(伏羲九针)和减伤/反弹类(海龙金身/金钟罩，会作用在伤害很大的炸弹上)最强，必须把效果数值压得很小；
禁锢(概率0.5)最强，降到0.2~0.25；穿透/持续伤害/回复真气偏弱。
物理伤害(开天辟地爪)没有可调数值，且双招里只要有一招带物理，整个双招都变成物理，所以靠高消耗(210)压价。

### 已知局限
- 学出来的均衡不唯一：同一张表可能落在"炸弹为主(约9回合)"或"单招双招拉锯(约22回合)"两种局面，开天辟地爪的使用率在这两种里相差很大(1%~12%)，是最不稳定的一个。
- 评测用的双方属性是对称的(HP1100/ATK1200/MP1700/敏捷21/回真气42)，没有区分玩家和售货员；招式使用率的测量误差约±30%，所以±10以内的威力/消耗差异没有意义。
- 游戏里的敌方AI现在是训练出的通用模型(`battle/ai.h`，权重`Resource/act/ai_weights.bin`)，不再是随机出招；这里评测用的是更早的表格式策略(已删除)。

- **强度公式(对手属性怎么增减)**：对称对战中强度大致正比于 `健康^a x 武力^1.0 x 真气^0.65`，a从第1式的约0.3增长到第10式及以后的约0.77。
  即第10式以后，相对健康的权重约为 武力1.3 : 真气0.85；第1式因为健康在低阶不敏感，武力和真气的相对权重更高(约3.4和2.2)。
  - 保持强度：健康x1.3 配 武力x0.8(或真气x0.6)；武力x1.2 配 真气x0.76。
  - 组合测试(同一张表，对称对打)：武力+真气互换的胜负差在±0.14以内，健康+武力的互换在±0.1以内，三项同时x1.3并相应压低真气的组合在±0.06以内；变动越大误差越大。
  - 武力最适合作"调节难度"的旋钮；真气次之；健康最敏感。
- **单调**：消耗、威力、效果数量都不小于低一式，用游戏解析器检查通过。
- **局限**：评测用固定类别策略和均匀的招式选择；对打双方属性相同；模拟次数为了速度压低，强弱度量的误差约±5%；效果数值是你设定的，强弱差异大的地方只能靠改效果参数。

### 规则调整记录(2026-10-25，未重新平衡各招式第一式)
- **跳过敏捷翻倍**(`SKIP_AGI_FACTOR=2`)：对方没被正面应对的普通招式，被攻击的一方如果在跳过(含被禁锢而无法出招，但选积攒不算)，敏捷翻倍计算闪避，双方敏捷相同时躲开概率80%；被禁锢的跳过方也能闪避。
- **真气炸弹**：积攒时每次消耗当前真气的40%(`ACCUMULATE_FRACTION`)，按10倍(`BOMB_ACCUMULATE_MULTIPLIER`)存进炸弹；释放时对手受 (累积量-对手出招威力)x0.75，自己受 累积量x0.2(`BOMB_BACKFIRE_FACTOR`)，不再带敏捷修正项；锈蚀场地下对双方的系数都是0.5(`BOMB_RUST_FACTOR`)。
- **反弹是减伤的升级版**：有反弹效果的一方，只承受反弹之后剩下的伤害，被反弹的那部分全部还给攻击者(反弹和减伤同时存在时，先减伤再反弹)。
- **海龙金身、金钟罩**的基础威力(第1~20式)全部减半，消耗不变。
- **双招自己构造场地效果**：双方出招的最终属性没有产生场地效果时，再分别看双方的出招，双招用它的两个基础招式的属性(金火灼烧/金水锈蚀/土火扬尘/土水泥沼)构造场地效果，同样加入场地。
- 上面这些调整之后，之前的"第一式平衡"和"各式强度"的数值不再适用，需要重新评估。
- **跳过要损失敏捷、敏捷每回合恢复**(个人属性，和每回合回复真气同类，`Cultivator`构造函数参数`agiLoss`默认1、`agiRecover`默认0.2)：
  每跳过一次(含被禁锢而无法出招，但选积攒不算)损失`agiLoss`点敏捷；跳过之后敏捷不能低于1，付不起时这回合的跳过没有闪避；每回合开始自动恢复`agiRecover`点，不超过初始敏捷。
  付得起时，这次跳过用翻倍(`SKIP_AGI_FACTOR`)的敏捷闪避。敏捷现在是小数，状态条里显示 当前/上限。
  注意：初始敏捷是20多的时候，损失1点只让躲开率下降约1~2个百分点(连续跳4次从81%降到75%)，想让这条规则明显抑制连续跳过，要把AGI初始值或`agiLoss`调到和AGI同一量级。

## increase / shield 招式效果(2026-10-26)

两个新的招式效果，PvP也生效；招式文件里写成 `increase 0.2` 和 `shield 强度 持续回合数`。`xiaohua.txt`末尾有两个测试家族(`测试增量`/`测试护盾`第1~20式)，
都是无属性、消耗/威力和同式的无招完全一样，只多一个效果，用来测平衡，不是正式招式。

- **increase `r`**：每个修炼者记着上一回合出的招(单招=1个，双招=两个基础招式)各自的"家族+式号+已连续步数"(`Cultivator::PeekChain/CommitChain`)。
  本回合出家族F的第k式，上一回合链里有(F, k-1)就是步数+1，否则步数0(新起点，没有加成)。积攒/放炸弹/跳过/被禁锢/空炸弹把链清空；命中与否不影响；
  双招里只要包含这一招就算连着。威力 = 基础威力 x (1 + r x 步数)，**独立的increase乘区**；双招每个基础招式用自己的r和步数，再乘`DUAL_POWER_FACTOR`
  (所以increase不并进双招自己的效果列表，见`DualAction`)。例：r=0.2，第18式原威力、第19式x1.2、第20式x1.4，从第1式连到第20式的第20步是x4.8。
  威力在`Controller::ApplyPower`里算好后用`Action::SetPower`写回招式对象，所以`CheckTurn`里读`GetPower()`的对拼/炸弹/闪避分支都不用改。战报：出招后一行"连招增伤，威力+N%"。
- **shield `强度 回合`**：出招时(不需要命中)给自己加一块盾，**每次出招一块新盾，各自独立计时，同时存在**。持续回合含出招当回合，每回合结束-1，到0移除。
  受到伤害时先过减伤，**再过护盾**(`Controller::ApplyShield`)：每块盾都被减去同一个伤害值，穿透量 = 伤害 − 最大那块盾的当前强度(多盾的好处只是各自计时，容量不叠加)，
  强度打光的盾移除；穿透量再进入物理转换/反弹/吸收/30%-60%健康判定。反弹**只反弹穿透量**，盾没破时不反弹。炸弹自伤、持续伤害、反弹回来的伤害也先过盾。
  战报："获得N点护盾"(subject>=0)、"的护盾抵挡了N点伤害"(subject=-1)。

## 特性系统(外部效果，2026-10-26，`modifier.h/.cpp`)

装备/秘诀/丹药/场地都用同一套"特性"(`Modifier`)：**种类 + 数值 + 属性掩码 + 条件 + 持续回合 + 执行时机 + 来源**，给谁加由`Controller::AddModifier(holder, m)`的持有者参数决定。
特性存在`Cultivator::Mods()`里；PvP没有特性时行为不变；暴击基础值`SetCritBase`默认0(不暴击、不多抽随机数)，PvE对局创建时设成5%/+50%。
**网页版`ai.html`有同样的实现和"特性调试"面板**(可以给双方加特性测平衡)；C++和JS逐场景对拍(`scenrun`脚本)一致。

文本格式：`mod <种类> <数值>[%] [attr=…] [cond=…] [dur=…] [timing=…] [src=名字]`，`#`开头是注释。
- `attr=`：逗号分隔 none metal wood water fire earth all(五行属性的招) elements(金木水火土) any，省略=全部(每个属性一个bit，按`ATTRIBUTE_TYPE`)。
- `cond=hp<50`：持有者的hp/atk/mp/agi占上限的百分比低于(<)/高于(>)阈值才生效(条件是独立参数，可挂在任意种类上，查询数值时判断)。
- `dur=`：持续回合数，-1=永久(默认)；每回合`EndTurn`-1，到0移除。建议在回合之间添加(在回合中途添加的，那一回合算第一回合)。
- `timing=start|end`：每回合类的执行时机，回合开始(默认)或结束。
- 同种类的数值**取加和，持续时间各算各的**。数值后加`%`：每回合类/立即类按上限的百分比，触发类按这次伤害量，`base_power`按该招基础威力，`*_max`按基础上限。

| 种类 | 含义和接入点 |
|---|---|
| `mp_round atk_round hp_round` | 每回合回复(+)/扣除(-)真气/武力/健康，`ExecModifiers`在回合开始/结束执行；武力/健康扣到0会死(`Cultivator::AdjustATK/AdjustHP`)；真气回复仍受上限和2倍爆体约束 |
| `skip_agi` `agi_recover` `agi_max` | 跳过扣敏捷调整(`SkipLoss`)、每回合敏捷回复调整(`RecoverAGI`)、敏捷上限增减(`GetMaxAGI`)；初始敏捷只在开局赋值，之后改的都是敏捷上限 |
| `mp_max` | 真气上限增减(`GetMaxMP`有效上限，`GetBaseMaxMP`基础上限)；"真气>2x上限即死"的阈值跟着有效上限走 |
| `acc_ratio` `bomb_power` | 单次积攒比例调整(基础0.2，夹到0~1)；炸弹威力增减(炸弹乘区=积攒能量 x 场地 x 炸弹倍率，和招式乘区无关) |
| `base_power` `dmg_dealt` `dmg_taken` | 招式乘区：x属性基础威力(加算进基础伤害)、自己造成伤害增减(增伤乘区)；`dmg_taken`是易伤，**只增不减**(负数解析失败、直接添加也无效)，和减伤效果(海龙金身)同一个乘区，见下面"受到伤害乘区" |
| `crit_rate` `crit_dmg` | 暴击率/暴击伤害增减；暴击倍率=1+暴击伤害，出招时掷一次(座位顺序固定，保证联机/重放一致) |
| `field_mult` | 场地x属性伤害倍率增减，以1为基准(灼烧本身是1.5，所以灼烧时再+0.5就是x2.0)，在`TakeDamage`里按出手方的特性算 |
| `dodge` `hit` | 闪避率/命中率乘区，和锈蚀/扬尘在同一乘区、数字加和：闪避区=1+加和−锈蚀(1)，最终闪避率=原闪避率x闪避区；命中区=1+加和−扬尘(0.5)，够1必中不抽随机数。没有特性时锈蚀/扬尘的结果和以前一样 |
| `cost` | x属性消耗调整(0.2=+20%)，和泥沼x1.5同层先后各自取整 |
| `deal_mp/atk/hp` `take_mp/atk/hp` | 造成/受到x属性伤害时给持有者回复(+)/扣除(-)真气/武力/健康，`ApplyDamageTriggers`；%=按这次伤害量 |
| `rebound` `immune` | 受到x属性伤害的反弹比例(加到反弹效果上，夹到0~1)；免疫x属性(该属性伤害变0) |
| `now_mp/atk/hp/agi` `now_field` `clear_field` `unlock` | 立即类：添加时马上执行、不保存、没有持续回合；`now_field`的数值是场地效果枚举(11灼烧 12锈蚀 13扬尘 14泥沼)；`unlock`移除禁锢 |
| `now_shield` | 立即类：立即给持有者加一块护盾，数值=强度，`attr=`=盾的五行属性(金木水火土可多选，`all`=五个齐全，不写=无属性盾)，`dur=`=持续回合(-1=不随回合衰减，到被打光)；日志沿用"获得N点护盾" |
| `resist` | 对x属性(金木水火土)的抗性增减，数值是**增量**(0.5=+50%)；见"玩家五行属性"一节；常驻类，支持`dur`/`cond`/`src` |
| `elem_power` | 自己拥有的属性的招式的威力倍率增减(基础1.5，增量)，夹到>=0、无上限；`attr=`限定招式属性；常驻类 |

**出招威力的乘区装配**(`Controller::ApplyPower`，先算完所有乘区再进对拼/炸弹结算)：
`单个基础招式 = (基础威力 + base_power加成) x increase(1+r x 步数)`；双招 = `DUAL_POWER_FACTOR x Σ`；
然后依次 x 暴击(1+暴击伤害) x 增伤乘区(1+dmg_dealt加和)。同乘区内加算，乘区之间相乘。场地乘区在`TakeDamage`里(灼烧1.5，特性可以加减)，不在出招威力里。
结果夹到int范围(PvE百万级、炸弹几十万，int够用)。

已知取舍：反弹回来的那一份伤害也会触发特性(出手方/受击方按反弹方向对调)；易伤和减伤一起在`TakeDamage`里结算(见"受到伤害乘区")，所以不再影响对撞时的出招威力，炸弹和持续伤害同样吃；对拼里的命中判定用先手座位的命中乘区；
每回合开始类特性导致的死亡由调用方在`StartTurn`之后检查存活(网页版`checkEnd`和UE的`puzzle_wxdj.cpp`回合推进处都已处理)；UE的PvE入口(给玩家/敌人传入特性列表、调`SetCritBase`)还没接，需要另行批准。

## 玩家五行属性(2026-10-26，`def.h` `ElementBit/ElementCovers`、`Cultivator::SetElements/Resist/ElemPowerMul`)

玩家有金木水火土五个独立开关，可任意组合：`Cultivator::elements`是位掩码(第n位=`ATTRIBUTE_TYPE`值n，和`Modifier.attrMask`同一编码)，默认0=无属性。
**PvP强制双方无属性**(`online.js`的`newBattle`显式`setElements(0)`)；双方都无属性、没有新特性时，战斗结果和随机数序列与以前逐位一致(固定种子300局对拍通过)。
PvE的入口：网页`ai.html`状态条里的"五行"勾选框(跨开新局保留)；UE的`WxdjPuzzle::SetParam`，剧情参数`elem=金木 enemy_elem=火`(`Wxdj.script`的`start_puzzle`参数)。

"覆盖"判定`ElementCovers(mask, attr)`：无属性永不覆盖；金木水火土要有对应位；**五行(ALL)要五位齐全**。双招用合成后的属性。

- **威力**(`ApplyPower`)：自己覆盖招式属性时，招式威力 x`ElemPowerMul`(基础1.5 + `elem_power`特性加和，夹到>=0)，是独立乘区(和暴击/增伤/易伤相乘)；无属性招式不加成。
- **护盾**：`ShieldEffect`带五行掩码`mask`。招式的`shield`效果生成的盾取出招者**当前**的`elements`；`now_shield`特性的盾属性由参数指定。
  受伤时(`ApplyShield(object, amount, attr)`)，盾的`mask`覆盖伤害属性则这块盾扣的量减半(向上取整，等价于容量翻倍)；
  穿透量=伤害−max(各盾有效容量)，盾打光后剩下的伤害不减半。没有同属性的盾时和以前完全一样。无属性伤害不触发。
- **属性抗性**：每个玩家对金木水火土各有抗性x(100%=1.0)：拥有该属性基础1.5，否则1.0，再加`resist`特性的增量，夹到>=0、无上限。
  **实际伤害 = 结算伤害 x 2/(x+1)**：x=1不变，1.5→x0.8，0→x2。五行(ALL)伤害要玩家五个属性都拥有才计算，取五个抗性的平均值；无属性伤害不处理。
  在`TakeDamage`(两个入口)里，现有减伤/场地倍率之后、护盾之前，x=1时跳过；取整四舍五入。顺序：威力 → 抗性 → 护盾 → 物理拆分/反弹。
- AI的特征没变(`features.h`)：AI看不到双方的五行属性，旧模型继续可用，但对五行玩家的判断会偏差，重训时再加。

顺手修了一个已有的崩溃：`ExecEffect`里持续伤害(`dot`)结算会走`TakeDamage`→`ApplyShield`把打光的盾从`effects[i]`里移除，导致原来持有的引用/下标失效(C++段错误，JS下标错位)；现在按值持有`shared_ptr`并在伤害后重新定位下标。

## 受到伤害乘区：减伤和易伤合并(2026-10-26)

减伤效果(海龙金身)和易伤特性(`dmg_taken`)是同一个乘区，在`TakeDamage`(两个入口)里结算：**乘区 = 1 + 易伤加和 − 减伤比例**，加算；实际受到的伤害 = 伤害 x 乘区。
- 易伤**只增不减**：`ParseModifier`对负数返回false，`ModifierSet::Add`忽略负数的`dmg_taken`，`Controller::Vulnerability`取max(0, 加和)。减伤只来自减伤效果，所以乘区不会变成0。
- 目前最小的受到伤害比例就是第20式海龙金身的减伤80%，乘区0.2；比例没法更小(没有别的减伤来源)。
- 易伤原来算在**出招威力**里(会抬高对撞时的威力)，现在统一挪到扣血这一步：对撞胜负只看双方威力和五行克制，不再受易伤影响；炸弹、持续伤害原来就在扣血这一步算。`Controller::TakenZone`已删除。
- 位置：免疫 → 场地倍率 → **受到伤害乘区(减伤+易伤)** → 属性抗性 → 护盾 → 物理拆分/反弹。没有易伤特性时走原来的`amount x (1-减伤比例)`(float运算)，结果与以前逐位一致。
